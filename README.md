# LLM Surgeon (`surgeon`)

![version](https://img.shields.io/badge/version-0.1.0-blue)
![rust](https://img.shields.io/badge/rust-2021_edition-orange)
![pure rust](https://img.shields.io/badge/pure_Rust-no_C_build_dependency-success)
![MCP](https://img.shields.io/badge/MCP-stdio_server-purple)
![platforms](https://img.shields.io/badge/platforms-Windows_tested_%7C_Linux_and_macOS_compile--checked-lightgrey)

`surgeon` is a command-line tool and an MCP server that inspects and edits the MLP weights of local language models (SafeTensors, and quantized GGUF in place), on the CPU, in pure Rust. Instead of retraining a model, it adds or subtracts a direction vector, merges a LoRA or applies a low-rank patch, and then measures what changed.

[Version française](README.fr.md)

Terminal messages are in French. Every output in this file is a real run, copied without colors (`NO_COLOR=1`). Unless a block says otherwise, it ran on a tiny fake Qwen2 model (4 layers, hidden size 16) generated by `examples/make_fake_qwen2.rs`: it is an "example on a fake mini-model", not a real model.

## 1. Concept and use cases

<a id="what-is-surgery"></a>
### 1.1 What is model surgery?

A language model is a very large set of numbers, the weights. Training adjusts them slowly with lots of data. Weight surgery edits a few of them directly, in one pass, to push the model's behaviour in a chosen direction.

> **For beginners**
> Think of a mixing console with sliders. Retraining a model is like asking the band to relearn the song. Surgery is nudging one slider by a measured amount. Here the "slider" is a vector (a list of numbers) and the amount you push is a single number called `alpha`.

Where this analogy is wrong, on purpose:

- A model has no labelled slider per concept. A direction is estimated from examples, so it can be noisy, and it usually mixes several things.
- The same weights serve many behaviours. Moving one thing can move others, and the effect is not guaranteed to be linear or small.
- The vector lives in a space of hundreds or thousands of dimensions (896 for the 0.5 B model of the quick start), not on a single axis.
- A real console can be put back exactly. Here "subtract then add" is not bit-exact because of rounding; the way back is the backup.

> **For experts**
> The editable object is a matrix `W`: an MLP projection (`gate_proj`, `up_proj`, `down_proj`), the attention output `o_proj` or the input embeddings `embed_tokens`, in a SafeTensors model or a quantized GGUF. `surgeon` broadcasts a vector over its rows or columns (`W <- W - alpha v`), removes a direction from the matrices that write into the residual stream (`project_out`, a LEACE eraser or a plain directional ablation), adds a low-rank delta (`.surgery`, LoRA), or re-rounds a quantized GGUF block. Everything is a deterministic, auditable edit of stored bytes; nothing is trained.

<a id="why-not-retrain"></a>
### 1.2 Why not simply retrain?

Both approaches have their place. This table is qualitative: it contains no measured figure.

| | Classic fine-tuning | Weight surgery with `surgeon` |
| --- | --- | --- |
| Data needed | A labelled or curated training set | A handful of contrastive prompts to find a direction, or none if you already have a vector, a LoRA or a checkpoint pair |
| Compute | Gradient training, usually on a GPU | Forward passes on a few prompts, then one write; CPU only |
| Reversibility | Keep the old checkpoint | Verified SHA-256 backup, automatic rollback on failure |
| Precision | Learns broad, rich behaviour | Coarse, mostly linear edit; side effects are possible |
| Main risks | Forgetting, cost, overfitting | Unintended behaviour change, weak or noisy directions, edits lost under quantization |

<a id="use-cases"></a>
### 1.3 Use cases

- Try activation-steering ideas as a permanent weight patch (`extract`, then `apply`), and compare the result with the original model (`bench`).
- Turn the difference between a base and a fine-tuned checkpoint into a compact low-rank patch (`diff`) or a PEFT LoRA adapter (`lora extract`).
- Fold a PEFT LoRA adapter into the base weights (`lora merge`).
- Patch a quantized GGUF in place, with a fidelity report per tensor (`apply --gguf`).
- Let an AI agent do the above through typed MCP tools, confined to chosen folders and always backed up (`surgeon mcp`).
- Compare direction-extraction methods (`mean_diff`, `svd`, `leace`) and plug in your own through the Rust extension API (`plugins list`).

<a id="non-goals"></a>
### 1.4 What the tool does not do

- It does not train or fine-tune anything, and it does not download models.
- `patch.json` edits MLP projections only. `diff` and `lora` also cover attention tensors.
- `extract`, `autotune`, `bench dump` and the preview tab run Qwen2 / Qwen2.5 (`model_type: "qwen2"`) only, on the CPU.
- It does not run a chat server or an inference API. `eval` and `bench ppl|eval` drive an external llama.cpp that you provide.
- The `.surgery` format is applied from the CLI only, not through MCP, and the dashboard is not exposed through MCP either.
- It cannot guarantee that an edit does what you intend or keeps the model safe: you must measure.

<a id="glossary"></a>
### 1.5 Glossary

| Term | Meaning here |
| --- | --- |
| Weight | A learned number stored in the model file. |
| Activation | The intermediate vector a layer produces while the model reads a prompt. |
| Layer | One repeated block of the network; layers are numbered from 0. |
| Steering vector | A direction in activation space (for example "positive minus negative") estimated from prompts. |
| Quantization | Storing weights on fewer bits (Q8_0, Q4_K...) to save memory; values land on a coarse grid. |
| SafeTensors | A simple, safe tensor file format used by Hugging Face models. |
| GGUF | The single-file model format of llama.cpp, often quantized. |
| LoRA | A low-rank adapter `B A` added to a weight matrix instead of retraining it. |
| Perplexity | How surprised a model is by a text; lower is better, compared before and after a patch. |
| KL divergence | A distance between two probability distributions; here between the next-token distributions before and after a patch. |
| Pass@1 | Share of questions answered correctly by one greedy answer. |

## 2. Quick start

<a id="install"></a>
### 2.1 Install

1. Install the Rust toolchain from <https://rustup.rs> (tested with Rust 1.97). On Windows you also need the MSVC Build Tools; on Linux a C linker (`cc`). No dependency compiles C code: `tests/deps_purity.rs` fails if a known C-building crate shows up in `Cargo.lock`.
2. Get the code and install the binary.

```bash
# fetch the sources
git clone https://github.com/truekiwwy/LLM-Surgeon.git
cd LLM-Surgeon
# install the binary in $HOME/.cargo/bin (%USERPROFILE%\.cargo\bin on Windows)
cargo install --path .
# check that it runs
surgeon --version
```

```text
surgeon 0.1.0
```

If you prefer not to install, build with `cargo build --release` and use `target/release/surgeon` instead of `surgeon`.

**Step 4. Extract a steering vector.** What it does: runs the model on both prompt sets, and writes `normalize(mean(pos) - mean(neg))` measured at layer 2.

```bash
# estimate a direction at layer 2 from the two prompt files
surgeon extract --model qwen2-mini --pos-prompts pos.json --neg-prompts neg.json --layer 2 --out direction.safetensors
```

```text
[EXTRACT]  Qwen2 · couche 2 · resid_post · pooling last  qwen2-mini
[LOAD]     poids chargés 37/37 tenseurs · f32 · 34.9 KiB
[FORWARD]  pos 6/6 · neg 6/6
[VERDICT]  d′ 2.23 · accuracy 92% · ‖Δ‖ 3.378
[WRITE]    direction.safetensors
  ! seulement 6 prompts positifs (au moins 8 recommandés)
  ! seulement 6 prompts négatifs (au moins 8 recommandés)
```

What it means: `d′` and `accuracy` say how well the direction separates the two prompt sets (higher is better); the warnings say six prompts per set is too few for a reliable direction (fine for a demo). Two files were written: `direction.safetensors` (one 1D f32 tensor named `direction`, plus metadata) and `direction.safetensors.stats.json` (the projection of every prompt). If it fails with exit code 7, the config, tokenizer or weights are invalid or the direction is degenerate; with exit code 2 an argument is wrong (an existing `--out` needs `--overwrite`).

**Step 5. Write the patch.** Save this as `patch.json`. It subtracts half of the vector from `down_proj` in layers 1 and 2. The vector has the size of the hidden dimension, which indexes the rows of `down_proj`, hence `"axis": "cols"` ([why](#patch-format)).

```json
{
  "schema_version": 1,
  "operations": [
    { "id": "steer-down", "layers": "1-2", "projections": ["down_proj"],
      "operation": "subtract", "vector_file": "direction.safetensors",
      "vector_tensor": "direction", "alpha": 0.5, "axis": "cols" }
  ]
}
```

**Step 6. Dry run, then apply.** `--dry-run` validates everything and lists the tensors that would change, writing nothing. Keep a pristine copy to compare against in step 7, and create the backup folder (it must exist).

```bash
# keep an untouched copy of the model for the comparison below
cp -r qwen2-mini qwen2-orig
# dry run: nothing is written
surgeon apply --model qwen2-mini --patch patch.json --dry-run
# real run, with the backup in an existing folder
mkdir backups
surgeon apply --model qwen2-mini --patch patch.json --backup-dir backups
```

```text
[APPLY]    patch.json · 1 opérations
[DRY-RUN]  steer-down · 2 tenseurs · vecteur de 16
           model.layers.1.mlp.down_proj.weight
           model.layers.2.mlp.down_proj.weight
```

```text
[APPLY]    patch.json · 1 opérations
[BACKUP]   backups\model.safetensors.bak-1794263372  ✓ sha256 vérifié
[SHIFT]    steer-down terminée · Δmax 0.2570 · 2 tenseurs
[COMMIT]   modèle patché · 0.0 s
```

What it means: a backup of the shard was copied and its SHA-256 verified before any write; two tensors were shifted by at most 0.257; the commit succeeded. If the backup folder does not exist the command stops with exit code 3 and the model is untouched (`erreur : backup : dossier de backup inexistant : nope`). A malformed patch gives exit code 2.

**Step 7. Verify the effect.** Dump the logits of both models on the same prompts and compare them.

```bash
# logits of the original and the patched model on the same prompts, then their comparison
surgeon bench dump --model qwen2-orig --prompts pos.json --out before.safetensors
surgeon bench dump --model qwen2-mini --prompts pos.json --out after.safetensors
surgeon bench logits --before before.safetensors --after after.safetensors
```

```text

[WRITE]    before.safetensors
[BENCH]    dump · 6 prompts · 24 positions · vocab 64 · f32
[WRITE]    after.safetensors

  pires prompts : #4 0.1118 · #5 0.0692 · #1 0.0517 · #0 0.0229 · #3 0.0225
```

What it means: the patch measurably changed the next-token distributions (mean KL 0.049; the top-1 token changed on 45.8 % of positions). The tool cannot tell you whether that change is the one you wanted: that is for you to judge. Add `--warn-kl 0.05 --fail-on-warn` to turn it into a gate (exit code 9).

**Step 8. Roll back.** There is no `undo` command: restore the backup and check the hash.

```bash
# put the backed up shard back
cp backups/model.safetensors.bak-* qwen2-mini/model.safetensors
# both hashes must be identical
sha256sum qwen2-orig/model.safetensors qwen2-mini/model.safetensors
```

## 3. Advanced guide and reference

<a id="envelope"></a>
### 3.1 Conventions: JSON envelope, exit codes, environment

Global options, valid before or after any subcommand: `--json` (machine-readable output), `-v`, `-vv`, `-vvv` (verbosity), `-h`, `-V`. With `--json`, every command prints one envelope on stdout; the same envelope is what the MCP tools return.

```text
{"ok": true, "command": "check", "exit_code": 0, "data": {...}, "error": null, "warnings": []}
```

| Field | Meaning |
| --- | --- |
| `ok` | `true` when `exit_code` is 0. |
| `command` | Name of the command (`bench logits`, `lora merge`...). |
| `exit_code` | The process exit code, also set on failure. |
| `data` | The command-specific result, `null` on failure. |
| `error` | `null`, or `{"kind": "...", "message": "..."}` (plus `issues` for invalid arguments). |
| `warnings` | Non-fatal messages. |

Failure example: `{"ok":false,"command":"apply","exit_code":2,"data":null,"error":{"message":"patch illisible missing.json : ...","kind":"invalid_patch"},"warnings":[]}`.

Exit codes:

| Code | Meaning |
| --- | --- |
| 0 | Success |
| 1 | General failure: insufficient resources, unreadable model, missing llama.cpp binary, Ctrl-C, `tui` without an interactive terminal |
| 2 | Invalid input: arguments, patch, prompts, paths; nothing was touched |
| 3 | Execution failed; the model is intact (never touched, or restored from the backup) |
| 4 | Critical: rollback failed, or no backup and the model was left partially patched |
| 5 | `eval`: unhealthy model (loops, failed expectations); no export |
| 6 | `eval`: GGUF export failed |
| 7 | `extract` or `autotune`: invalid config, tokenizer or weights, degenerate direction, NaN/Inf, singular or ill-conditioned system |
| 8 | `bench`: run failed (llama.cpp process, unreadable output, incompatible dumps, generation) |
| 9 | `bench --fail-on-warn`: a threshold was exceeded (the report is still in `data`) |
| 70 | Internal error (panic), reported after the terminal is restored |

Environment variables: `NO_COLOR` (plain output), `CLICOLOR_FORCE` (colors even when piped), `LLAMA_CPP_DIR` (llama.cpp folder), `SURGEON_KERNEL` (`scalar`, `avx2`, `avx512` or `neon`), `SURGEON_MCP_ALLOW_DIRS` (allowed folders of `surgeon mcp`).

<a id="commands"></a>
### 3.2 Command reference

Each card gives the usage, every option with its default taken from `--help`, the `--json` content of `data`, and the exit codes beyond the common ones. The help texts of the binary are partly in French; the descriptions below are translated. The examples of this chapter run in the `demo` folder of [path A](#path-a) (the repository is then `..`), and build on its files.

<a id="cmd-check"></a>
#### `surgeon check`

Computes the RAM and VRAM needed to load a model and gives a verdict, without loading it.

```text
surgeon check [OPTIONS] --model <MODEL>
```

| Option | Default | Role |
| --- | --- | --- |
| `--model` | required | Model file or folder. |

<a id="cmd-extract"></a>
#### `surgeon extract`

Runs a Qwen2 forward pass on two prompt sets and writes a steering direction. Pure Rust, CPU, `model_type: "qwen2"` only.

```text
surgeon extract [OPTIONS] --model <MODEL> --pos-prompts <POS_PROMPTS> --neg-prompts <NEG_PROMPTS> --out <OUT>
```

| Option | Default | Role |
| --- | --- | --- |
| `--model` | required | Folder with `config.json`, `tokenizer.json` and the `*.safetensors` (or an index). |
| `--pos-prompts` | required | JSON array of strings or of `{"text": ...}`, JSONL, or plain text (one prompt per line). |
| `--neg-prompts` | required | Same format, the opposite set. |
| `--layer` | 20 | 0-based layer, must be below `num_hidden_layers`. |
| `--out` | required | Output `.safetensors` (one 1D f32 tensor `direction`). |
| `--pooling` | `last` | `last` (last token) or `mean` (mean over the prompt). |
| `--site` | `resid_post` | `resid_post` (residual stream after layer L) or `mlp_out` (MLP output). |
| `--chat-template` | `none` | `none` (raw text) or `chatml` (Qwen chat format). |
| `--max-tokens` | 512 | Prompts are truncated on the right beyond this. |
| `--dtype` | `auto` | `auto` (f32 if it fits in RAM, else bf16), `f32`, `bf16`. |
| `--overwrite` | off | Replace an existing `--out` and its companion files. |
| `--method` | `mean_diff` | `mean_diff`, `svd` or `leace` (see `surgeon plugins list`). |
| `--svd-center` | off | `svd`: center the paired differences (pairs in arbitrary order). |
| `--leace-shrinkage` | 0.1 | `leace`: shrinkage λ in [0, 1] of Σ toward tr(Σ)/d·I; 0 is the pseudo-inverse. |
| `--leace-rcond` | 1e-10 | `leace` with λ = 0: relative threshold of the kept eigenvalues. |
| `--holdout-frac` | 0 | Held-out fraction (by index) for out-of-sample diagnostics; needs 10 or more prompts per set. |
| `--rank` | 1 for `svd`, all for `leace` | Directions of the subspace, 1 to 64: `svd` keeps that many singular vectors, `leace` with `--labels-file` at most that many. `mean_diff` stays rank 1. |
| `--labels-file` | none | `leace`: JSON array with one label per prompt, positives then negatives: an integer class index, or an array of `m` numbers. All labels are erased at once. |

Outputs: the direction, `<out>.stats.json` (projection of every prompt, read by the dashboard) and, for `leace`, `<out>.leace.safetensors` (`a`, `b`, `mean`, `u_whitened`). With `svd --rank` above 1, `<out>.subspace.safetensors` holds `a = b = V_k`; with `leace --labels-file`, `a` and `b` of the `.leace.safetensors` have shape `[k, hidden]`. Both go as they are to a `project_out` operation, and `data.method_diagnostics.subspace` gives each component (`sigma_t`, `explained_variance_cumulative`, `d_prime`, `gram_BtA_error`). Writes are atomic. `data`: `out_path`, `stats_path`, `layer`, `method`, `hidden_size`, `n_pos`, `n_neg`, `dtype_used`, `duration_ms`, `stats`, `warnings`. Exit codes: 7 for model or computation failures; 2 for invalid arguments, including `unpaired_prompts` for `svd`.

<a id="cmd-apply"></a>
#### `surgeon apply`

Applies a `patch.json` (SafeTensors, or GGUF with `--gguf`) or a `.surgery` file in place, after validating everything, with a verified backup and automatic rollback.

```text
surgeon apply [OPTIONS] --model <MODEL> --patch <PATCH>
```

| Option | Default | Role |
| --- | --- | --- |
| `--model` | required | SafeTensors file or folder, or a `.gguf` with `--gguf`. |
| `--patch` | required | `patch.json`, or a `.surgery` file (detected by its `SURG` magic). |
| `--dry-run` | off | Validate and list the tensors; write nothing. |
| `--backup-dir` | next to the model | Backup folder; it must already exist. |
| `--no-backup` | off | Refused by validation when the patch sets `backup: true`, and always refused with `--gguf`. |
| `--gguf` | off | Patch a quantized `.gguf` in place (lossy: values are re-rounded to the file's grid). A `.gguf` without this flag is refused. |
| `--requant` | `keep-scales` | GGUF: `keep-scales` or `recompute` ([details](#formats)). |
| `--no-verify` | off | GGUF: skip the read-back check after writing. |
| `--force-no-backup` | off | GGUF: patch without a backup; a failure leaves the file modified. |

| `--no-prefetch` | off | No OS prefetch hint nor intermediate flush. |
| `--scale` | 1 | `.surgery` only: `W <- W + scale * delta`. |
| `--verify-base` | `warn` | `.surgery` only: check each base tensor against the stored hash: `strict` (error, nothing written), `warn`, `off`. |
| `--max-rank` | 64 | `project_out`: largest rank of a subspace (rows of the `a` and `b` tensors); a larger one is refused before any write. |
| `--arch-spec` | none | Architecture spec (JSON, `surgeon schema --kind arch`) instead of detection: which tensors are targets and how they are oriented. |

`data`: `backups`, `report` (`dry_run`, `backup_path`, per-operation tensors with `elements_modified`, `max_abs_delta`, `nan_or_inf_produced`, `rolled_back`), `io` (bytes, chunks, throughput, page faults), `warnings`; with `--gguf`, also `gguf` (fidelity per tensor). Exit codes: 2 invalid patch (nothing touched), 3 execution failed (model intact), 4 critical (rollback failed).

<a id="cmd-bench"></a>
#### `surgeon bench`

Five modes that measure what a surgery changed. The recipe: dump the logits of both models on the same prompts, compare them, check perplexity, an exact-match benchmark and, for a surgery on refusals, the refusal rate, then decide. Thresholds only produce warnings, except under `--fail-on-warn` (exit code 9, report still in `data`). Two more subcommands, `judge-sample` and `judge-eval`, measure the optional judge model of `refusal` against human labels.

With `--judge llm` or `--judge both`, a judge model labels each answer once the generation is over. The marker fields above do not change; the verdicts go to `data.judge`, with `items[]` (`index`, `label`, and the judge's own text in `raw`) and the count of each label in `labels`.

The `refusal` role uses the labels `complied`, `refused_explicit`, `refused_soft`, `partial`, `degenerate` and `other`; its rate counts `refused_explicit` and `refused_soft`, plus `partial` under `--partial-as-refusal`. <a id="generation"></a>
#### Sampling, batching and backends (`bench eval`, `bench refusal`)

Without these options, `bench eval` and `bench refusal` print and write what they did before (greedy decoding, one prompt at a time, same report); the report only gains a `data.generation` block (backend, sampling, samples, batch) once an option differs from its default or the backend from the historical one.

**Sampling.** `--temperature 0` is greedy decoding, token for token what it was. Above 0, the logits go through the chain of llama.cpp's default sampler, in its order: repetition penalty, top-k, top-p, min-p, temperature, then one draw from a softmax computed in f64. Each prompt and sample has its own random stream, xoshiro256++ seeded by SplitMix64 from `--seed` and the pair (prompt, sample): a sample draws the same tokens whatever the batch, the order of the jobs or the number of samples, with this binary on this CPU family. The llama backends receive the same parameters and the seed of each stream (as `--temp`, `--top-k`... flags, or as fields of the server request), but apply them with their own sampler: their draws are neither those of the native backend nor bit-identical across llama.cpp builds.

**Statistics.** With `--samples N` (N above 1, temperature above 0), each prompt is answered N times. `data.items[]` gains a `sample` index, and `data.generation.sampled` gives the rate of each prompt (`per_prompt`), their `mean`, a 95 % bootstrap interval that resamples prompts, not answers (2000 resamples, fixed seed: the same answers give the same interval), the dispersion within a prompt (`within_prompt_variance`, the mean of p (1 - p)) and between prompts (`between_prompt_variance`). With a baseline, `baseline_sampled` and `delta`, the mean difference of the per-prompt rates and its bootstrap interval. The answer-level pairing (`paired`) assumes one answer per prompt and is left out when N is above 1.

**Batching.** `--batch-size B` decodes up to B sequences together (native backend). Each step runs the projections and the MLP of the B sequences as one matrix product, so every weight is read once per step for the whole batch; attention stays per sequence, on its own KV cache and at its own position, so there is no padding and a sequence's tokens do not depend on the others. A finished sequence leaves the batch and the next one takes its place. Every prompt is prefilled alone. `--jobs J` runs J batches in parallel threads, all in one rayon pool: `--threads`, else `RAYON_NUM_THREADS`, else every core. Once an option differs from its default, the run warns when the pool has more threads than the machine has cores, when `--threads` overrides `RAYON_NUM_THREADS`, and when other `surgeon` processes are running (they share the cores and the memory bandwidth). In greedy decoding, batched and sequential tokens are identical in the tests (mini models with and without sliding window, B from 1 to 8, one or three workers); their logits differ by at most 1e-5 relative, the rounding of a matrix product with several rows instead of one, which could only change a token on a near tie. A timeout (`--timeout-secs`) counts from the first token of a sequence, not from its wait for a place in the batch.

**Backends.** `native` is the pure Rust generator (CPU). `llama-completion` runs one llama.cpp process per prompt, as `bench eval --backend llama` always did. `llama-server` starts one llama.cpp server for the whole bench and sends it up to `--batch-size` requests at once. A SafeTensors folder given to a llama backend is first converted to a temporary GGUF (as `bench eval` does), deleted at the end. The server gets nothing but these flags, each spelled as its own `--help` lists it, the run failing when one is missing: `-m`, `--host 127.0.0.1`, `--port` (a free port), `--api-key` (128 random bits), `-np`, and `-c`, `-ngl`, `-t` from `--ctx-size`, `--gpu-layers`, `--threads`. No other argument can reach it, from the command line or from MCP. It is killed when the bench ends, fails or is cancelled. Requests go over HTTP/1.1 on the loopback only (standard library sockets, no TLS, no network crate), streamed as server-sent events, each with its timeout.

**GPU.** Whether `llama-server` uses a GPU depends on how llama.cpp was built (CUDA, Vulkan, HIP, Metal) and on `--gpu-layers`; surgeon itself stays on the CPU (its candle backend has no GPU feature, on purpose). To check the offload, run the server once by hand with the same model and `-ngl`: its log prints a line such as `load_tensors: offloaded 25/25 layers to GPU`, and `GET /props` reports its settings; when a run fails, surgeon puts the tail of the server's stderr in the error. GPU runs are not reproducible bit for bit, even at temperature 0 (the order of the kernels' reductions varies): compare rates with their intervals, not answers byte for byte.

The `llama-server` backend is tested against `examples/fake_llama_server.rs` (health, slots, API key, streaming, timeouts, a server that dies, a taken port, the kill), not against a real llama.cpp, which this repository's tests do not install.


```text
[REFUS]    réponses 0/18 · 0.0 % · IC95 [0.0 ; 17.6]
```

<a id="patch-format"></a>
### 3.3 `patch.json` and the `rows` / `cols` axes

`surgeon schema` prints the full JSON Schema (draft-07) of `patch.json`, and that schema is the reference. In short: a patch has `schema_version` (1), an optional `description`, `backup` (default `true`) and a non-empty `operations` array applied in order; any error cancels the whole patch. An operation has:

| Field | Role |
| --- | --- |
| `id` | Unique identifier, repeated in the report. |
| `layers` | `"all"`, `"10-20"`, `"3,5,7"`, an array `[10, 11]`, or `{"start": 10, "end": 20}` (inclusive). |
| `projections` | Non-empty, no duplicates: `gate_proj`, `up_proj`, `down_proj`, and for a SafeTensors model `o_proj` (attention output of each layer) and `embed_tokens` (input embeddings; they belong to no layer, so `layers` does not filter them). |
| `operation` | `subtract`, `add` or `project_out`. |
| `vector_file` | `.safetensors` or `.json` vector; relative to the folder of the patch. |
| `vector_tensor` | Tensor name when the SafeTensors file holds several; forbidden with `.json`. |
| `vector_tensor_b` | `project_out` only: the read direction `b` (`vector_tensor` is then `a`). |
| `alpha` | Strength in [-100, 100]; `|alpha| > 5` raises a warning. For `project_out`, in [0, 1]. |
| `axis` | `rows` or `cols` (default `cols`). |
| `rank` | `project_out` only: the expected rank, i.e. the rows of `a` and `b` (`[rank, hidden]`, 1 for the 1D form). Tensors of another rank are refused. Absent: the rank of the tensors. |
| `allow_non_projector` | `project_out` only: accept `alpha = 1` when `‖B^T A - I‖ > 1e-3` (not a projector), with a warning. Default `false`: refused. |

The formula for `subtract` and `add`, on a row-major `[rows, cols]` tensor: `W[r][c] <- round(W[r][c] ∓ alpha * v[i])`. The product `alpha * v[i]` is computed once per vector element in f32, then each weight takes one f32 addition and is rounded to nearest even into the stored dtype (bf16, f16 or f32). `alpha = 0` is a strict no-op. Weights are `[out, in]` (Llama and Qwen layout):

```text
gate_proj / up_proj : [intermediate, hidden]      down_proj : [hidden, intermediate]

axis "rows"  (len(v) = cols)                      axis "cols"  (len(v) = rows)
W[r][c] -= alpha * v[c]                           W[r][c] -= alpha * v[r]

   c0  c1  c2  c3                                    c0   c1   c2   c3
r0 -v0 -v1 -v2 -v3                                r0 -v0  -v0  -v0  -v0
r1 -v0 -v1 -v2 -v3                                r1 -v1  -v1  -v1  -v1
r2 -v0 -v1 -v2 -v3                                r2 -v2  -v2  -v2  -v2
```

With `rows`, every row receives the same vector (one value per column); with `cols`, every row gets a single value `v[r]` repeated along the row. A steering vector lives in the residual stream, whose size is `hidden`. For `gate_proj` and `up_proj` that size is the number of columns, so use `rows`; for `down_proj` it is the number of rows, so use `cols`. `o_proj` (`[hidden, hidden]`) writes like `down_proj`: `cols`. `embed_tokens` (`[vocab, hidden]`) holds one residual vector per row: `rows`. A wrong choice fails validation with a length mismatch before any byte is written.

> **For experts**
> `project_out` removes what `b` reads from the matrices that write into the residual stream: `W' = W - alpha * a (b^T W)` for `down_proj` and `o_proj`, `W' = W - alpha * (W b) a^T` for `embed_tokens` (its rows are the residual vectors). With `a` and `b` from a `.leace.safetensors` it is the LEACE eraser; with `a = b = v`, a unit direction (`"vector_tensor": "direction", "vector_tensor_b": "direction"`), it is a directional ablation. One operation with `"layers": "all"` and `"projections": ["down_proj", "o_proj", "embed_tokens"]` covers every writer; `gate_proj` and `up_proj` read from the stream and are refused. In bf16 a small delta can round away: measure the result.
>
> `a` and `b` can also be `[k, hidden]` tensors, one direction per row (`<out>.subspace.safetensors` of `svd --rank`, or the `.leace.safetensors` of `leace --labels-file`): `W' = W - alpha * A (B^T W)` then removes the `k` directions in one pass over the weights, so each weight is rounded once whatever `k`, while `k` successive rank-1 operations would round `k` times in an order that changes the result. The 1D form gives the same bytes as before. Before any write, `apply` checks that `a` and `b` have the same rank, that it matches `rank` when the operation sets it and does not exceed `--max-rank` (64; the MCP server keeps this default), and that `‖B^T A - I‖_F <= 1e-3` when `alpha = 1`: otherwise `alpha = 1` removes something else than the subspace read by `b`, and a `[k, hidden]` patch is refused unless `allow_non_projector` is `true` (the 1D form stays accepted, with a warning). These checks read the tensors, so a refusal is exit code 3 with the model intact, not an invalid patch. A quantized GGUF takes the same recipe, with a measured residual: see [GGUF residual writers](#gguf-writers).
>
> When `embed_tokens` is a target and the model ties it to the output projection (no `lm_head.weight`, as Qwen2.5-0.5B), `apply` first detaches the head so the logits are not deformed: it rewrites the shard with `lm_head.weight`, a byte copy of the unpatched embeddings, and sets `"tie_word_embeddings": false` in `config.json` (and completes `model.safetensors.index.json` for a sharded model). The shard grows by the size of the embeddings. `--dry-run` announces it in `data.untie_lm_head` and writes nothing; the shard and `config.json` are both backed up and restored on failure. Without `config.json` next to the model the patch is refused.

### 3.4 Formats

| Format | Where it is used |
| --- | --- |
| SafeTensors (file, shards, index) | Read and patched in place by `inspect`, `apply`, `diff`, `lora`, `eval`; memory-mapped. Dtypes of the shift kernels: bf16, f16, f32. |
| GGUF v3, single file, little endian | `inspect`, `apply --gguf`; target types F32, F16, BF16, Q4_0, Q4_1, Q5_0, Q5_1, Q8_0, Q4_K, Q5_K, Q6_K. Written by `eval --export-gguf` through llama.cpp. |
| `.surgery` | Low-rank patch written by `diff`, applied by `apply`; magic `SURG`, specified in [docs/SPECIFICATION.md](docs/SPECIFICATION.md); header schema: `surgeon schema --kind surgery`. |
| PEFT LoRA adapter | `adapter_model.safetensors` (keys `base_model.model.<path>.lora_A.weight` and `lora_B.weight`) plus `adapter_config.json`; read by `lora merge`, written by `lora extract`. |
| Logits dumps | `.safetensors` written by `bench dump`; `bench logits` also reads `.npy` and `.pt`. |

| `--requant` | What changes in a block | Use it when |
| --- | --- | --- |
| `keep-scales` (default) | Only the integers of the elements whose patched value differs; the scales are kept byte for byte; values past the grid are clipped and counted | small shifts, about one quantization step |
| `recompute` | New scales for every touched block (Q8_0, Q4_0, Q4_1, Q5_0, Q5_1: their `quantize_row_*_ref`; Q4_K, Q5_K and Q6_K: min/max with scales rounded up, no clipping) | strong shifts; it is not the iterative `llama-quantize`, and there is no importance matrix |

Each patched tensor gets a fidelity report: `intended_shift_norm`, `realized_shift_norm`, `realized_over_intended`, `correlation_intended_realized`, `unchanged_fraction`, `saturated_elements`, `nmse_vs_exact`. A ratio under 0.5 or a correlation under 0.8 means the shift is smaller than half a quantization step and was lost or turned into noise.

> **For experts**
> An in-place write on a file of tens of GB is guarded in six steps: everything is checked before writing (targets, types, whole blocks, vector lengths, free disk space for the copy); a full backup is made and its SHA-256 verified; a crash marker `<model>.surgeon-inprogress` (backup path, original SHA-256, time) is written before the first byte; tensors are written chunk by chunk, each chunk computed and checked (finite scales and values) in a copy first, and the header, metadata and tensor table are never rewritten (their SHA-256 is compared before and after); after the flush a second mapping re-reads every patched tensor and compares it to the SHA-256 computed while writing (`--no-verify` skips this); any error restores the backup, and the marker is removed after the commit or the rollback. The test suite cannot validate a patched file against a real llama.cpp: check that it loads and run `surgeon bench ppl` before use.

<a id="gguf-writers"></a>
#### GGUF residual writers: `project_out` on a quantized file

The full ablation recipe of the SafeTensors path works on a GGUF as is: one `project_out` on `embed_tokens`, `o_proj` and `down_proj`, every layer. Each tensor is dequantized, projected exactly as the SafeTensors engine does (`W' = W - alpha A (B^T W)` on `ffn_down` and `attn_output`, whose rows are the residual stream, in two passes; each row of `token_embd` on its own), then requantized with `--requant`. With `keep-scales` the written bytes are those of `requant(project(dequant(W)))`, byte for byte (the tests check it against an independent decoder, for every patchable type).

Requantization adds noise, and the part of that noise read by `B` brings back some of the erased direction. So a GGUF ablation is never complete; it is measured, per tensor, in `data.gguf.tensors[]`:

| Field | Meaning |
| --- | --- |
| `residual_fraction` | `‖B^T deq(W')‖ / ‖B^T W‖` (`‖deq(W') B‖ / ‖W B‖` for the embeddings): the share of the read component still there, `1 - alpha` at best for a projector. |
| `requant_residual_fraction` | `‖B^T (deq(W') - W_exact)‖ / ‖B^T W‖`: the part brought back by the requantization, what `--residual-target` bounds. |
| `refine_passes` | Quantization passes measured. |

`--refine-passes N` (1 to 5) measures up to `N` quantizations of each tensor: pass `n + 1` requantizes `W_exact - A C` with `C` the sum of the residuals read so far, starting again from the original bytes; it stops once `requant_residual_fraction <= --residual-target` (default 0.05) and writes the pass with the smallest residual. The correction is far below a quantization step, so it lowers the residual statistically, never to zero; a target not reached, or a pass that did not lower the residual, is a warning. Nothing is written while measuring: every pass is a read-only sweep, then one write pass replays the chosen bytes, under the same guards (pre-flight, backup, crash marker, read-back, rollback). The pre-flight types every target before the first write and reports the work, an order of magnitude of the time and the backup size in `data.gguf.preflight`.

When the file has no `output.weight` (tied embeddings, as Qwen2.5-0.5B), llama.cpp reads `token_embd` as the output head too: editing it changes the logits as well, so `apply` refuses it unless `--allow-tied-embedding`, and then says so in the report. With an `output.weight`, only `token_embd` (the writer) is changed, never the head (a reader).

<a id="architectures"></a>
#### Architectures and the exactness of an ablation

`surgeon` describes each architecture as data (`src/arch`, `surgeon schema --kind arch`): the name patterns of each role, for SafeTensors and for GGUF, and the facts of its topology. The roles are `embed` (one residual vector per row, `[vocab, hidden]`), `attn_out` and `mlp_out` (the writers of the residual stream, `[hidden, *]`: dense, per expert, fused experts `[E, hidden, inter]`, shared experts), `mlp_gate` and `mlp_up` (readers, for `add` / `subtract`) and `router` (listed, never modified). A pattern matches the end of a name, any prefix allowed (`model.`, `model.language_model.`...), `{layer}` and `{expert}` standing for numbers: `layers.{layer}.mlp.experts.{expert}.down_proj.weight`. The patch projections map onto the roles: `embed_tokens`, `o_proj`, `down_proj` (every MLP writer), `gate_proj`, `up_proj`. The architecture comes from `config.json` (`model_type`, then `architectures`), from `general.architecture` in a GGUF, or from `--arch-spec`; when nothing is recognized, the historical Llama/Qwen naming applies, exactly as before.

| id | `model_type` | GGUF | `project_out` | Native forward | Checked on |
| --- | --- | --- | --- | --- | --- |
| `llama` | `llama`, `mistral` | `llama` | exact | yes | forward |
| `qwen2` | `qwen2` | `qwen2` | exact | yes | forward |
| `qwen3` | `qwen3` | `qwen3` | exact | yes | forward |
| `qwen2_moe` | `qwen2_moe` | `qwen2moe` | exact | no | topology |
| `qwen3_moe` | `qwen3_moe` | `qwen3moe` | exact | no | topology |
| `deepseek` | `deepseek_v2`, `deepseek_v3` | `deepseek2` | exact | no | topology |
| `gemma2` | `gemma2` | `gemma2` | approximate | no | topology |
| `gemma3` | `gemma3`, `gemma3_text` | `gemma3` | approximate | no | topology |
| `phi3` | `phi3` | `phi3` | exact | no | topology |
| `falcon` | `falcon` | `falcon` | exact | no | topology |
| `command-r` | `cohere` | `command-r` | exact | no | topology |

An ablation by weights (`project_out` on every writer) is **exact** when the residual stream is the sum of the embeddings and of every sublayer output and each norm only feeds a sublayer: pre-norm, sequential or parallel (Falcon, Command-R), RMSNorm or LayerNorm alike. It is **approximate** when a learned norm is applied to a sublayer output before the addition (Gemma 2/3: `post_attention_layernorm` and `post_feedforward_layernorm`), whose per-coordinate scale does not commute with the projection, or when the model has writer biases (`attention_bias`, `mlp_bias`, Falcon's `bias`: detected from the `.bias` tensors of the checkpoint itself), which are not projected. It is **unsupported** when a spec declares writers it cannot patch (`unprojected_writers`, learned position embeddings for instance) or has no pattern for a writer role. The test suite measures it: on the real forward of `llama`, `qwen2` and `qwen3` the direction erased from every writer leaves less than 1e-5 of the residual stream after every layer (about 0.1 before); for the others, a residual stack with each built-in's topology (norm kind, post-sublayer norm, parallel block) leaves under 1e-12 when exact and over 1e-3 when approximate. "topology" means just that: their real forward was not run.

MoE: every expert's `down_proj` is a writer; a fused `[E, hidden, inter]` tensor (transformers v5) or `ffn_down_exps` (GGUF, `ne = [inter, hidden, E]`) is erased expert by expert, shared experts like any writer, the router never. `add` / `subtract` have no axis on a fused 3D tensor and are refused there. These models have no native forward: the direction comes from a dense model with the same hidden size, which is a limit (the MoE residual stream may not hold the concept on the same direction).

`apply` decides before reading anything for writing: an `exact` ablation runs, an `approximate` one is refused (`error.kind = "approximate_ablation"`, exit code 2) unless `--accept-approximate`, then warned and reported in `data.arch.accepted_approximate`; an `unsupported` one is refused (`unsupported_architecture`). `add` / `subtract` (steering) are not ablations and are never gated. <a id="theory"></a>
### 3.5 Theory as implemented

All linear algebra is pure Rust in f64 (`src/linalg`: cyclic Jacobi, thin SVD through the smaller Gram matrix, Cholesky) and independent of the thread count.

- **`mean_diff`** (default): `v = normalize(mu+ - mu-)` over the pooled activations.
- **`svd`** (contrastive): prompts are paired by index (otherwise exit code 2, `unpaired_prompts`); with `dX_i = x+_i - x-_i`, `v` is the first right singular vector of `dX`, i.e. the dominant eigenvector of `(1/N) dX^T dX`, oriented so that `<v, mu+ - mu-> >= 0`. `dX` is not centered by default, because centering removes the mean difference, which is the concept axis itself; `--svd-center` is for pairs in arbitrary order. Diagnostics: the first five singular values, `sigma1^2 / sum(sigma^2)`, the cosine with `mu+ - mu-`, and a split-half cosine (even against odd pairs). A warning appears when `sigma2 / sigma1 > 0.9` or with fewer than 8 pairs. With `--rank k`, the first `k` right singular vectors `V_k` (orthonormal, each oriented along `mu+ - mu-`; fewer when `dX` has a lower rank) go to `<out>.subspace.safetensors` as `a = b = V_k`, an orthogonal projector; `direction` is still the first one.
- **`leace`**: `r(x) = x - a b^T (x - mu)` with `S_l = (1 - l) S + l tr(S)/d I`, `w = S_l^(-1/2) (mu+ - mu-)`, `u = w / |w|`, `a = S_l^(1/2) u` (parallel to `mu+ - mu-`) and `b = S_l^(-1/2) u`, so that `b^T a = 1`. `a` says where to write and `b` what to read. The written `direction` is `a / |a|`, hence the same direction as `mean_diff`; `a`, `b`, `mean` and `u_whitened` go to `<out>.leace.safetensors`. `--leace-shrinkage 0` is the pseudo-inverse on the data subspace (`--leace-rcond`).
- **`leace` with `--labels-file`** (labels `z` in R^m; class indices become one-hot rows over the classes present): `S_XZ = (1/n) sum (x_i - mu)(z_i - z_mean)^T` (`d x m`), `M = S_l^(-1/2) S_XZ = U S V^T`, `r` the number of singular values above `rcond * s_1` (at most `--rank`), then `A = S_l^(1/2) U_r` and `B = S_l^(-1/2) U_r`, so that `B^T A = I_r` and `r(x) = x - A B^T (x - mu)`. When no singular value is cut, the cross-covariance with every label vanishes in sample. `U` comes from the `m x m` Gram matrix of the columns of `M`: no `d x d` matrix is formed. The diagnostics per component are `sigma_t`, `explained_variance_cumulative`, `d_prime` and, with `--holdout-frac`, `holdout_cross_cov_residual`.
- **Honest limits of LEACE**: the cross-covariance between `r(x)` and the label is zero in the sample for any positive definite `S_l`. "No linear predictor beats a constant" is a population guarantee, not a sample one: with fewer prompts than dimensions a classifier can still separate the erased sample. Only `--holdout-frac` (fit on the rest, measure on held-out prompts, reported as `holdout_cross_cov_ratio`) says whether the erasure generalizes.
- **`autotune`**: the readout is `s_i = <pool(h_i^R), v>` at layer R (site, pooling and template of the vector); the target is `y_i = t_i - s_i^0` (`neg_mean_proj` for `suppress`, `pos_mean_proj` for `amplify`, `--target-projection`, or a per-prompt `target`); the response `F_il = (s_i(delta_l) - s_i^0) / delta` is measured in memory with the engine's own shift on the stored bytes (bf16 rounding included); then `alpha = (F^T F + l I)^(-1) F^T y` by Cholesky, with `l` fixed or chosen by closed-form leave-one-out (`e_i / (1 - h_ii)`, 17 points from 1e-6 to 1e2). R² is uncentered (there is no intercept). The fitted `alpha` are applied together and measured again. Side effects are not measured: run `surgeon bench` afterwards.

Definitions used by the `bench` reports:

- **KL**: `KL(before||after) = sum p_i (log p_i - log q_i)` with `p = softmax(before)` and `q = softmax(after)`, in f64 through log-sum-exp; the "before" distribution is the reference. Terms with `p_i = 0` are skipped. A token finite before and `-inf` after makes the position infinite: it is counted in `kl_infinite_positions` and kept out of `kl_mean`, `kl_max` and `kl_p95` (nearest rank).
- **Cosine**: `cosine_probs_mean` compares probability vectors; `cosine_logits_mean`, labelled apart, compares raw logits.
- **Top-k**: `top1_shift_rate` is the share of positions whose argmax changes (ties go to the lowest index); `topk_set_change_rate` the share whose set of `k` best tokens differs; `topk_overlap_mean` the mean `|A ∩ B| / k`.
- **Delta perplexity**: `ppl - ppl_baseline`, rounded to 4 decimals (what llama.cpp prints) before the strict comparison with `--warn-delta`: `7.4 - 7.2` is `0.20000000000000018` in floating point and must not exceed 0.2. The delta is `within_noise` when `|delta| <= sqrt(err^2 + err_baseline^2)`; a negative delta is an improvement, never a warning.
- **Pass@1**: exact match of one greedy sample (`--temp 0 --top-k 1 --seed 42`). The 95 % interval is Wilson's. With `--baseline-model` the comparison is paired (`lost` and `gained` question ids). With the default 50 questions the interval is wide (40 correct out of 50 gives [67.0 %, 88.8 %]), so only large regressions are conclusive; the report warns when fewer than 100 questions were scored.

```text
[VERDICT]  décalage prévu -0.0371 · mesuré -0.0354 · écart à la cible 3.6594 → 3.6390
[WRITE]    tuned.json
  ! couches [3] au-delà de la lecture (couche 2) : sans effet sur elle, exclues
  effets secondaires non mesurés ici : appliquer sur une copie puis surgeon bench (dump, logits, ppl)
```

On this random mini-model the responses do not generalize across prompts, so the leave-one-out search picks the strongest `l` and the fit explains about 1 % of the shift (R² 0.012). That is an honest answer, not a bug: the measured shift (-0.0354) still matches the prediction (-0.0371). `tuned.json` is an ordinary patch (`backup: true`, one `subtract` per layer).

<a id="performance"></a>
### 3.6 Performance

`apply` shifts with SIMD kernels chosen at run time: AVX-512F, AVX2 with F16C (x86_64), NEON (aarch64), else scalar. `SURGEON_KERNEL=scalar|avx2|avx512|neon` overrides the choice; an unavailable level falls back to the best one with a warning, so an illegal instruction cannot be reached. Every level is designed to write the same bytes as the scalar path: each element costs one f32 addition `old + delta` followed by the same round-to-nearest-even into bf16 or f16, with `half`'s NaN rule.

> **For experts**
> There is no fused multiply-add anywhere. The product `alpha * v[i]` is computed once per vector element, the kernel only adds. A fused multiply-add rounds once instead of twice and would drift from the scalar reference by a last bit; and the operation is memory bound anyway, so fusing would buy nothing. Tensors are written by chunks (`--prefetch-chunk-mib`, default 64) with OS hints (`madvise` on Unix, `PrefetchVirtualMemory` on Windows) and an asynchronous flush of the previous chunk; `--no-prefetch` turns both off. `data.io` of `apply` reports bytes, chunks, failed hints, time, throughput and page faults.

The kernel and I/O numbers below come from one run of `examples/bench_kernels.rs` made for this README on 2026-11-09, with this command (it writes a 2 GiB scratch file and takes about 90 seconds):

```bash
# kernel and I/O benchmark, prints Markdown tables
cargo run --release --example bench_kernels
```

Machine: Intel Core i5-12400F (6 cores, 12 threads, AVX2 and F16C, no AVX-512), 15.9 GB RAM, Windows 11 Pro, 12 rayon threads. In memory, 1 GiB buffer, 4096 columns; parallel `memcpy` of the same buffer measured 17 463 MiB/s (13 676 MiB/s on one thread):

| level | dtype | axis `rows` MiB/s | axis `cols` MiB/s | vs parallel memcpy (rows) |
| --- | --- | ---: | ---: | ---: |
| scalar | bf16 | 3 944 | 3 975 | 0.23 |
| scalar | f16 | 2 701 | 2 592 | 0.15 |
| scalar | f32 | 13 027 | 13 241 | 0.75 |
| avx2 | bf16 | 17 970 | 17 715 | 1.03 |
| avx2 | f16 | 17 601 | 18 077 | 1.01 |
| avx2 | f32 | 17 070 | 16 977 | 0.98 |

AVX-512 and NEON were not run: this CPU has neither. End to end (`shift_tensor` plus flush on a 2 GiB bf16 file already in the page cache) the same run gave 99 to 119 MiB/s with prefetch and 110 to 112 MiB/s without, with about 525 000 page faults either way: on this machine the write-back of dirty pages of the mapped file dominates, not the kernels, and prefetch does not remove page faults on Windows. A previous run of the same example on the same machine gave about 180 to 240 MiB/s, so treat end-to-end figures as dependent on the disk, the page cache and the OS; rerun the example on your machine. Direct I/O (`O_DIRECT`) is not implemented.

The rank-k `project_out` was measured in memory on the same machine on 2026-11-11, with this command (about 20 seconds once built):

```bash
# atomic rank-k pass against k successive rank-1 passes, best of 3 per cell
cargo test --release --lib rank_k_throughput -- --ignored --nocapture
```

Each cell is the atomic pass, then `k` successive rank-1 passes, in ms. `[896, 4864]` is the shape of a `down_proj` of Qwen2.5-0.5B, `[32768, 896]` a slice of its embeddings (the `embed_tokens` form); `a = b` are `k` orthonormal directions:

| tensor | dtype | k = 1 | k = 4 | k = 16 | k = 64 |
| --- | --- | ---: | ---: | ---: | ---: |
| `[896, 4864]` | bf16 | 3.6 / 3.4 | 5.9 / 15.4 | 9.6 / 53.2 | 48.8 / 219.5 |
| `[896, 4864]` | f32 | 3.4 / 3.4 | 4.0 / 10.9 | 9.4 / 40.0 | 49.1 / 157.7 |
| `[32768, 896]` | bf16 | 24.3 / 25.1 | 36.2 / 79.5 | 78.7 / 309.0 | 248.1 / 1306.8 |
| `[32768, 896]` | f32 | 22.1 / 23.6 | 35.3 / 68.8 | 75.1 / 249.2 | 254.4 / 986.3 |

At rank 1 both paths are the same code. From k = 4 the single pass is about 2 to 5 times faster, because the weights are read and written once instead of `k` times; it also rounds each weight once, which is the real reason for it. The cost grows with `k` once the `k x in` products dominate the memory traffic (about 170 MiB/s of bf16 weights at k = 64 against 2 300 MiB/s at k = 1). A second run of the same command was 5 to 40 % slower per cell, and up to twice as slow on the cells of a few milliseconds: treat these as orders of magnitude.

The reports of `bench logits` and `bench eval` were not benchmarked for this README, so no throughput is claimed for them.

<a id="mcp"></a>
## 4. Agents and MCP

<a id="what-is-mcp"></a>
### 4.1 What MCP is

The Model Context Protocol (MCP) lets an AI assistant call external tools through a standard JSON-RPC interface. `surgeon mcp` is a local MCP server on stdio: the client starts it as a subprocess and calls typed tools. It exposes the same engine as the command line, with the same `--json` envelope as result, but only through folders you allow.

<a id="tools"></a>
### 4.2 Tools

`surgeon mcp` serves nine tools (real answer of `tools/list`, also printed by `surgeon schema --kind tools`):

| Tool | Role |
| --- | --- |
| `surgeon_check` | RAM and VRAM budget of a model. |
| `surgeon_inspect` | Layers and MLP matrices, optional statistics. |
| `surgeon_apply` | Applies a patch in place (`dry_run` to check first); `gguf: true` for a quantized GGUF. |
| `surgeon_eval` | Loop and expectation checks, conditional GGUF export. |
| `surgeon_extract` | Steering vector from a Qwen2, Llama/Mistral or Qwen3 layer. |
| `surgeon_bench` | Measurement, with `mode` `dump`, `logits`, `ppl` or `eval`. |
| `surgeon_autotune` | Per-layer coefficients by ridge regression. |
| `surgeon_diff` | Difference of two checkpoints written to a new `.surgery`. |
| `surgeon_lora` | `mode` `merge` (adapter folded in place) or `extract` (adapter written). |

A real session on the fake model: the client sends `initialize`, `notifications/initialized`, then a `tools/call`. The server writes one line on stderr, then answers on stdout (the `initialize` answer is left out, and the answer line is cut):

```bash
# start the server on the current folder, read-only
surgeon mcp --allow-dir . --read-only
```

```text
surgeon mcp 0.1.0 : prêt sur stdio, 1 dossier(s) autorisé(s), lecture seule
{"id":2,"jsonrpc":"2.0","result":{"content":[{"text":"{\"ok\":true,\"command\":\"check\",\"exit_code\":0,\"data\":{\"available_ram_bytes\":4787773440,\"best_gpu\":null,\"model_bytes\":55528,\"required_ram_bytes\":2147547506,\"required_vram_bytes\":null,\"verdict\":{\"kind\":\"fits_in_ram_only\"},[...]
{"id":3,"jsonrpc":"2.0","result":{"content":[{"text":"{\"ok\":false,\"command\":\"inspect\",\"exit_code\":2,\"data\":null,\"error\":{\"message\":\"« model » : chemin hors des dossiers autorisés (--allow-dir)\",\"kind\":\"path_not_allowed\"},\"warnings\":[]}","type":"text"}],"isError":true,[...]
```

The first call (`surgeon_check` on `qwen2-mini`) succeeds; the second asks for `../elsewhere`, which is outside the allowed folder and is refused with `path_not_allowed`.

<a id="guardrails"></a>
### 4.3 Guardrails

- `--allow-dir` (repeatable, else `SURGEON_MCP_ALLOW_DIRS`, else the current folder): every path is resolved by the system (symbolic links, `..`) and must fall under an allowed folder; relative paths are relative to the first one.
- `--read-only`: refuses every tool that writes (`surgeon_apply`, `surgeon_extract`, GGUF exports, `surgeon_bench` in `dump` mode, `surgeon_autotune` with `out`, `surgeon_diff`, `surgeon_lora`).
- Backup imposed: a verified SHA-256 backup precedes any write, and a failed backup blocks the write. `backup: false` in a patch is honored only with `--allow-no-backup`.
- Cancellation: `notifications/cancelled` stops the running call, rolls back a partial patch and kills the running llama.cpp process; a cancelled extraction or dump leaves no file.
- Progress: with a `progressToken`, a `notifications/progress` is sent per tensor, prompt or chunk.
- A panic during a tool becomes a JSON-RPC error and the server keeps running.

Details and the protocol versions accepted: [docs/MCP.md](docs/MCP.md) (written in French).

<a id="client-config"></a>
### 4.4 Client configuration

The paths below come from the official documentation of each client, read on 2026-11-09; check the documentation of your client version if something differs. Replace `<MODELS_DIR>` with the absolute folder that holds your models.

Claude Code (user scope here; use `--scope project` to share a `.mcp.json` with a team):


Claude Desktop, in `claude_desktop_config.json` (`%APPDATA%\Claude\claude_desktop_config.json` on Windows, `~/Library/Application Support/Claude/claude_desktop_config.json` on macOS). Restart the application after saving. Backslashes of Windows paths are doubled in JSON (here the folder is `C:\models`):


Cursor, in `.cursor/mcp.json` (one project) or `~/.cursor/mcp.json` (global):

If the client cannot find `surgeon`, use the absolute path of the binary as `command`. Claude Code can also load the folder [`plugin/`](plugin) as a plugin (same server, `allow_dir` asked on activation, plus a safe-workflow skill; see [docs/PLUGINS.md](docs/PLUGINS.md)).

<a id="agent-recipe"></a>
### 4.5 A safe agent recipe

1. Copy the model into an allowed folder. The agent never touches the only copy.
2. `surgeon_check` on the copy.
3. `surgeon_bench` with `mode: "dump"` on the copy: the reference logits.
4. `surgeon_extract` a direction (at least eight prompts per set).
5. `surgeon_apply` with `dry_run: true`, read the tensors it lists.
6. `surgeon_apply` for real; the backup is imposed.
7. `surgeon_bench` `dump` again, then `logits`, then `ppl` and `eval` if llama.cpp is available.
8. Decide from the measured numbers. If it is bad, restore the backup. Announce no result that was not measured.

This is what the `safe-surgery-workflow` skill of the Claude Code plugin tells the agent. The same recipe from a shell, with the commands of [path A](#path-a): `check`, `extract`, `apply --dry-run`, `apply`, `bench dump`, `bench logits`.

<a id="llama-cpp"></a>
### 4.6 llama.cpp: what is used and how it is found

llama.cpp is optional and never bundled. It is used only by `eval` and `bench ppl|eval`, and for the GGUF export. The binaries and scripts looked for by the code:

| Used by | File looked for |
| --- | --- |
| `eval` | `llama-cli` |
| `eval --export-gguf` | `convert_hf_to_gguf.py` (or the legacy `convert-hf-to-gguf.py`) and its Python requirements, then `llama-quantize` (or `quantize`) |
| `bench ppl` | `llama-perplexity` (or the older `perplexity`) |
| `bench eval` | `llama-completion`, else `llama-cli` |

Search order: the folder given by `--llama-cpp-dir`, then the folder of the `LLAMA_CPP_DIR` environment variable (in both, the sub-folders `build/bin`, `build/bin/Release` and `build` are tried too), then the folders of `PATH`.

```bash
# bash: pass the folder once per command, or export it for the session
export LLAMA_CPP_DIR=$HOME/llama.cpp
surgeon bench ppl --model model.gguf --text text.txt --llama-cpp-dir $HOME/llama.cpp
```

```powershell
# PowerShell
$env:LLAMA_CPP_DIR = "$env:USERPROFILE\llama.cpp"
```

Through MCP the operator sets `LLAMA_CPP_DIR` for the server; the agent does not choose it.

<a id="architecture"></a>
### 4.7 Architecture and plugins

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (French) defines the vocabulary: the Surgery Engine at the core, the CLI and the MCP server as front-ends, and the extension points. In short, `surgeon` is split into modules (`hardware`, `engine`, `patch`, `extract`, `bench`, `eval`, `kernel`, `linalg`, `lora`, `surgery`, `tui`, `mcp`, `plugin`). One extension point exists today, `ExtractionMethod` (API `v0`, unstable): a Rust trait whose implementations are registered statically in a program that links the library. The `surgeon` binary only registers the three built-in methods, and `surgeon plugins list` shows them. [docs/PLUGINS.md](docs/PLUGINS.md) (French) walks through writing a method and describes a proposal for out-of-process plugins that is not implemented.

<a id="faq"></a>
## 5. FAQ, safety and troubleshooting

<a id="hardware-budget"></a>
### 5.1 Memory budget and `check` verdicts

`surgeon check` estimates, without loading anything: needed RAM = model size x 1.15 + 2 GiB margin (`--policy-ram-margin-gib` changes the margin), needed VRAM = model size x 1.20. Verdicts: `FITS IN VRAM` (a GPU has enough free memory; on unified memory the stricter of the two needs is checked once), `FITS IN RAM ONLY` (CPU fallback, slower), `INSUFFICIENT` (exit code 1, with the reason). The NVML warning means the NVIDIA library was not usable, so GPUs are ignored. Most commands, including `apply`, work by memory-mapping and need little RAM; `extract` and `bench dump` load the weights (`--dtype bf16` halves the memory; `auto` falls back to bf16 by itself, with a warning).

<a id="backups"></a>
### 5.2 Backups and automatic rollback

- `apply`, `lora merge` and the MCP tools copy each touched shard to the backup folder and verify its SHA-256 before writing. The backup folder must exist.
- On error, on a NaN or Inf in a result, or on cancellation (Ctrl-C, or `notifications/cancelled` in MCP), the original bytes are restored and the exit code is 3 (4 if the rollback itself failed, or if there was no backup and the model is partly patched).
- GGUF: a crash marker `<model>.surgeon-inprogress` is written before the first byte and removed after commit or rollback. If it is still there (crash, power loss), `apply` refuses to run: copy the backup named in the marker over the model, compare its SHA-256 with `original_sha256`, then delete the marker.
- There is no `undo` command: restoring is a file copy of the backup, as in [path A](#path-a). Applying the opposite `alpha` is not an exact undo, because of rounding.

<a id="windows-lock"></a>
### 5.3 Windows: `surgeon.exe` is locked by an MCP client

An MCP client keeps `surgeon.exe` running, so `cargo install --path .` fails with "Access denied". Close the client, or rename the running binary (Windows allows it) and install again:

```powershell
# Windows: rename the running binary
Rename-Item "$env:USERPROFILE\.cargo\bin\surgeon.exe" surgeon.old.exe
```

<a id="limits"></a>
### 5.4 Known limits

- `extract`, `autotune`, `bench dump`, `bench refusal` and the preview tab run a native forward for Qwen2/Qwen2.5, Llama 2/3, Mistral and Qwen3 only, on the CPU; large models need a lot of RAM. MoE models (Qwen2-MoE, Qwen3-MoE, DeepSeek) and Gemma, Phi-3, Falcon, Command-R have no native forward (`unsupported_architecture`): their weights can be patched, but the direction must come from a dense model with the same hidden size.
- Direction quality depends on your prompts: with few pairs a direction mixes concepts (the tool warns below 8 prompts per set). A good `d′` on the extraction prompts does not prove the direction generalizes.
- Patches smaller than a quantization step are lost in quantized GGUF files; shifts past the block range are clipped (`keep-scales`). Check `realized_over_intended`.
- `project_out` covers the residual writers of a SafeTensors model (`down_proj`, `o_proj`, `embed_tokens`); in a GGUF only the MLP projections are patchable. `bench refusal` counts refusal markers (English by default), and its optional judge model is reported as not calibrated until you measure it against your own human labels: read the answers. LEACE erasure is exact in the sample only; with fewer prompts than dimensions, check `holdout_cross_cov_ratio`. `autotune` fits and measures on the same prompts and does not measure side effects.
- `svd` and `leace` rely on Jacobi, limited to 1024 on the smaller side (prompts or hidden size).
- Benchmark samples are small by default (`bench eval --limit 50`): read the confidence interval.
- Logits dumps in f16 add rounding noise; prefer the f32 default.
- GPU offload of `bench ppl` can change the last digits between runs; the default `--n-gpu-layers 0` is reproducible.
- `apply --gguf`: single-file little-endian GGUF only; no importance matrix; the requantization is scalar (rows in parallel). It was not validated against a real llama.cpp by the test suite.
- The dashboard needs an interactive terminal of at least 80x24; otherwise use `--snapshot`.
- Terminal messages are in French.
- No license file is published: until one is added, default copyright applies (all rights reserved). The README carries no license badge for that reason.

<a id="responsible-use"></a>
### 5.5 Responsible use

Steering and weight surgery change what a model does, including its safety behaviour: a direction can remove refusals as easily as it adds them. Work on copies, evaluate after every patch, respect the license of every model you modify, keep the backups, and do not distribute a model whose safeguards you removed. A modified model can degrade or change in ways your tests did not cover.

<a id="troubleshooting"></a>
### 5.6 Troubleshooting

| Symptom | Likely cause | Action |
| --- | --- | --- |
| `erreur : backup : dossier de backup inexistant` (exit 3) | `--backup-dir` does not exist | Create the folder first. |
| `est un fichier GGUF : relancez avec --gguf` (exit 2) | A `.gguf` was given without `--gguf` | Add `--gguf`; re-rounding is lossy and never silent. |
| `--no-backup est refusé avec --gguf` (exit 2) | The backup copy is mandatory for GGUF | Remove it, or use `--force-no-backup` knowing a failure leaves the file modified. |
| `une application précédente a été interrompue` | A crash marker is left next to the GGUF | Restore the backup named in the marker, compare SHA-256, delete the marker. |
| `` `surgeon tui` nécessite un terminal interactif `` (exit 1) | stdin, stdout or stderr is not a terminal | Run in a real terminal, or use `--snapshot`. |
| `Terminal trop petit (80×24 minimum)` | Terminal or `--size` below 80x24 | Enlarge it. |
| `erreur : fichier de prompts ... JSON invalide` (exit 2) | `eval` prompts must be objects with `text` | Use `[{"id": "a", "text": "..."}]`; the extraction prompt files are plain strings. |
| `--llama-cpp-dir (ou LLAMA_CPP_DIR) requis` (exit 1) | llama.cpp not found | Build llama.cpp and pass its folder ([search order](#llama-cpp)). |
| `ressources insuffisantes` (exit 1) | The budget check failed | `--dtype bf16`, a smaller model, or close other programs. |
| `NVML indisponible` warning | NVIDIA library not usable | Harmless: GPUs are ignored and the model is planned for RAM. |
| `f32 ne tient pas en RAM : calcul en bf16` | Little free RAM | Expected; free memory for a full-precision dump. |
| `Access denied` on `cargo install` (Windows) | `surgeon.exe` still running | See [5.3](#windows-lock). |
| Boxes or blocks look broken | Font or encoding | Use a UTF-8 terminal with box-drawing characters (Windows Terminal). |
| A threshold fails the run (exit 9) | `--fail-on-warn` and a threshold exceeded | Read the report in `data`; relax or fix the patch. |
